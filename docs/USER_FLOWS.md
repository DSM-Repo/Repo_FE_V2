# User Flows

## 학생 포트폴리오 작성 흐름

1. 학생이 로그인한다.
2. 필수 상단 정보를 입력하거나 수정한다.
3. 문서형 에디터에서 본문을 작성한다.
4. 텍스트 스타일, 링크, 이미지, 인용 등을 추가한다.
5. 저장한다.
6. 필요하면 공개 상태를 변경한다.
7. PDF 변환 대상이 된다.

## 학생 공개 상태 변경 흐름

1. 학생이 자신의 레주메 페이지로 이동한다.
2. 공개 상태 스위치를 확인한다.
3. on/off를 변경한다.
4. 변경된 상태가 저장된다.

## 공개 포트폴리오 URL 흐름

1. 학생 또는 시스템이 학생별 공개 slug를 가진다.
2. 공개 상태가 on이면 외부 사용자는 slug 기반 URL로 포트폴리오를 볼 수 있다.
3. 공개 상태가 off이면 외부 접근은 제한된다.

예시:

```txt
/오혜민
```

Open Question: slug 중복, 예약어, slug 변경, 기존 URL redirect 정책을 어떻게 처리할 것인가?

## 선생님 학생 조회 흐름

1. 선생님이 로그인한다.
2. 학생 관리 화면으로 이동한다.
3. 반 버튼 또는 검색창으로 학생을 찾는다.
4. 학생 이름 옆에서 제출완료/미제출 태그를 확인한다.
5. 필요한 학생의 레주메를 연다.

## 선생님 피드백 흐름

1. 선생님이 학생 레주메를 연다.
2. 피드백 모드를 켠다.
3. 피드백을 남기고 싶은 영역을 선택한다.
4. 피드백을 추가한다.
5. 필요하면 피드백을 수정/삭제한다.

Open Question: 피드백 연결 단위를 문서 block, 텍스트 range, 섹션 중 무엇으로 볼 것인가?

## 전공 관리 흐름

1. 선생님이 전공 관리 화면으로 이동한다.
2. 전공을 생성한다.
3. 필요 없는 전공을 삭제한다.
4. 전공별 학생을 조회한다.

## 레주메북 변환 흐름

1. 선생님이 도서관 또는 레주메북 관리 화면으로 이동한다.
2. 변환할 대상 조건을 선택한다.
3. PDF 변환을 요청한다.
4. 변환 결과가 도서관에 반영된다.

## 내부 도서관 열람 흐름

1. 로그인한 사용자가 도서관으로 이동한다.
2. 레주메북 목록을 확인한다.
3. 연도/학년/기수, 전공, 반, 이름 검색으로 원하는 항목을 찾는다.
4. PDF Viewer로 레주메북을 연다.
5. 빠른 이동으로 학생 위치로 이동한다.
6. 필요하면 PDF를 다운로드한다.
