# Requirements

이 문서는 Repo-V2의 기능 요구사항 기준 문서입니다. `docs/MVP_SCOPE.md`는 초기에는 별도 작성하지 않고 이 문서에 포함합니다.

## 1차 MVP 범위

### 학생 기능

- 문서형 포트폴리오를 작성할 수 있어야 한다.
- 상단 필수 정보를 입력할 수 있어야 한다.
  - 이름
  - 학번
  - 학과
  - 이메일
  - 관련 링크
  - 한 줄 자기소개
  - 하위/상세 자기소개글
  - 보유 기술 스택
- 본문은 자유 문서형 에디터로 작성할 수 있어야 한다.
- 텍스트 스타일링을 지원해야 한다.
  - 글자 크기
  - Bold
  - 인용글
  - 링크 첨부
  - 이미지 첨부
- 학생은 자신의 레주메 공개 상태를 on/off 할 수 있어야 한다.
- 학생별 정해진 페이지 수 제한은 두지 않는다.

### 선생님 기능

- 학생을 조회할 수 있어야 한다.
- 반별 학생을 조회할 수 있어야 한다.
- 이름으로 학생을 검색할 수 있어야 한다.
- 학생의 이력서 제출 여부를 확인할 수 있어야 한다.
  - 제출완료
  - 미제출
- 학생 개인 레주메의 공개 상태를 on/off 할 수 있어야 한다.
- 전공을 생성할 수 있어야 한다.
- 전공을 삭제할 수 있어야 한다.
- 전공별 학생을 조회할 수 있어야 한다.
- 피드백 모드를 켜고 원하는 부분에 피드백을 추가/수정/삭제할 수 있어야 한다.

### 공개 상태 요구사항

- 학생과 선생님 모두 공개 상태를 자유롭게 변경할 수 있다.
- 최종 상태는 마지막으로 변경된 값으로 본다.
- TODO: 공개 상태 변경 이력 기록 여부를 결정해야 한다.

### PDF / 레주메북 요구사항

- 학생이 작성한 포트폴리오는 최종적으로 PDF로 변환될 수 있어야 한다.
- PDF를 기반으로 학교가 레주메북을 제작/배포하는 흐름은 유지한다.
- 선생님은 레주메북 변환을 실행할 수 있어야 한다.
- TODO: PDF 변환 책임이 프론트엔드, 백엔드, 별도 렌더링 서버 중 어디에 있는지 결정해야 한다.

### 내부 도서관 요구사항

- 로그인한 내부 사용자는 모두 레주메북 도서관을 볼 수 있어야 한다.
- 레주메북 목록을 볼 수 있어야 한다.
- 레주메북 PDF를 열람할 수 있어야 한다.
- PDF 다운로드를 지원한다.
- 반별/학생별 빠른 이동을 지원한다.
- 전공별 필터를 지원한다.
- 반별 필터 또는 조회를 지원한다.
- 이름 검색을 지원한다.

## 후순위 요구사항

- 기업/외부 사용자용 웹 뷰어 고도화
- 외부 기업 사용자를 위한 학생 탐색, 필터, 상세 조회 경험
- 외부 공개 URL 정책 고도화

## Non-goals

1차 설계/문서 하네스 단계에서 하지 않을 것:

- 기업/외부 사용자용 웹 뷰어 고도화
- 문서형 에디터, PDF 변환, 상태 관리, form/validation 등 미결정 항목을 근거 없이 무리하게 확정
- 제품 기능 구현
- 페이지 구현
- 레거시 구조 그대로 복제
- Figma 화면 기준의 세부 퍼블리싱 계획 확정
- 완전 자유형 웹사이트 빌더 수준의 포트폴리오 커스터마이징

## Backend / API Assumptions

백엔드도 Repo-V2에 맞춰 새롭게 설계될 예정입니다. 프론트엔드는 다음 영역을 함께 설계 가능한 전제로 둡니다.

- 로그인/권한
- 학생·선생님 계정
- 전공/반 데이터
- 이력서 저장 형식
- 피드백 저장 방식
- PDF 변환 책임

초기 API 도메인 후보:

- `auth`
- `users`
- `students`
- `majors`
- `resumes`
- `resume-documents`
- `feedback`
- `libraries`
- `pdf`
- `files`

이 목록은 확정 API 명세가 아니라 백엔드와 논의하기 위한 도메인 초안입니다.
