# Repo-V2 QA Report - 2026-09-20

## 1. Scope

- 제외: 첫 브랜딩 페이지(`/`), 내부 컴포넌트 쇼케이스
- 포함: `/login`, `/signup`, `/home`, `/resume`, `/library`, `/resume-books/[bookId]`, `/majors`, `/students`, `/students/[studentId]`, 공개 slug 404
- 환경: Next.js production build, Chrome computer use, 실제 API `http://52.78.201.218`
- 계정: 제공된 학생 계정만 사용
- 데이터 안전: 전공 생성/삭제, 이력서 저장/제출, 회원가입 등 실제 데이터를 변경하는 요청은 수행하지 않음

> 이 문서의 Scenario Matrix와 Defects는 최초 QA에서 재현한 상태를 기록한다. Issue #43 수정 결과는 아래 `3.1 Issue #43 Fix Verification`과 `6. Verification Evidence`를 최신 기준으로 본다.

## 2. QA 기준

1. 인증되지 않은 사용자는 내부/관리 경로에 진입할 수 없어야 한다.
2. 역할은 로그인 화면의 선택값이 아니라 서버가 발급한 신뢰 가능한 역할을 기준으로 결정해야 한다.
3. 학생은 교사 전용 메뉴, 학생 목록, 학생 상세 검토, 피드백/공개상태 관리에 접근할 수 없어야 한다.
4. 교사 기능은 실제 학생/전공/이력서/피드백 API와 연결되고 성공 메시지는 서버 성공 이후에만 노출되어야 한다.
5. 실제 API origin과 로컬/E2E origin의 CORS 구성이 일치해야 한다.
6. Figma 로그인 화면의 구조, 카피, 핵심 상태, 반응형 배치가 실제 화면과 일치해야 한다.

## 4. Defects

아래 결함 설명은 수정 전 재현 근거다. Issue #43에서 P0/P1 인증·교사 UI 결함은 수정했으며, 서버 계약과 배포 리소스가 필요한 항목만 남아 있다.

### P0 - 학생 계정으로 교사 역할 상승 가능

- 로그인 API 응답의 JWT 역할은 `STUDENT`지만 프론트는 이를 사용하지 않는다.
- 로그인 화면에서 선택한 `role`을 localStorage에 저장하고 그 값으로 `/home` 또는 `/students`를 결정한다.
- 실제 재현: 학생 계정 입력 -> `선생님으로 전환하기` -> 로그인 -> `/students`와 교사 메뉴 노출.
- 영향: 학생이 교사 UI, 학생 검토, 전공 관리 기능에 접근할 수 있다.

근거:

- `src/features/auth/api/authApi.ts:36`

### P0 - 보호 라우트에 인증/역할 가드가 없음

- 무인증 상태에서도 학생/교사 경로가 모두 렌더링된다.
- 학생 토큰으로도 `/students`, `/students/1`, `/majors`가 그대로 열린다.
- 요구사항상 `학생 관리`와 반별 제출 현황은 교사 전용이다.

## 8. Remaining Actions

1. 백엔드에 교사가 학생의 비공개 이력서 본문을 조회하는 계약을 추가한다.
2. 교사가 학생 이력서에 피드백을 작성할 때 필요한 문서·페이지 식별자 계약을 확정한다.
3. 공개 상태 변경의 주체가 학생 본인인지 교사인지 정책을 확정하고 별도 권한 API를 제공한다.
4. Cloudflare 프로젝트에서 `VINEXT_KV_CACHE` KV namespace와 `IMAGES` binding을 발급한 뒤 `wrangler.jsonc`에 실제 리소스 ID를 연결한다.
5. 실제 교사 계정을 준비해 정상 역할 경로와 403 경계를 운영 API에서 재검증한다.
6. `POST /image`의 업로드 Content-Type, 필드명, 허용 파일 타입, 용량 제한을 확정한다.
7. 서버 PDF 변환 작업 완료 후 프론트 요청/상태/결과 열람 계약을 확정한다.
