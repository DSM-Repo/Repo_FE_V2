# Publishing Guide

Figma 디자인을 실제 화면으로 옮길 때의 기준 문서입니다.

## UI Reference

사용자 제공 참고 영상:

- https://www.youtube.com/watch?v=fR8tsJ2r7Eg

이 영상은 UI 컴포넌트와 퍼블리싱 방향을 논의할 때 참고 자료로 사용합니다. 단, 영상 내용을 그대로 복제하지 않고 Repo-V2의 제품 방향, Figma 디자인, 접근성, 유지보수 기준에 맞게 해석합니다.

## 기본 원칙

- Figma를 기준으로 하되, 구현 안정성과 재사용성을 함께 고려한다.
- 공통 컴포넌트로 추출할 수 있는 UI는 반복 구현하지 않는다.
- 픽셀 단위 완벽함보다 제품 흐름과 유지보수성을 함께 본다.
- 문서형 에디터와 PDF Viewer는 일반 페이지보다 별도 검증 기준이 필요하다.

## 우선순위

1. 공통 레이아웃
2. 인증/권한별 진입 흐름
3. 학생 포트폴리오 작성 화면
4. 선생님 학생 관리/피드백 화면
5. 도서관/PDF Viewer 화면
6. 세부 인터랙션/애니메이션

## 반응형 기준

Repo-V2의 1차 퍼블리싱은 **웹 데스크톱 기준**으로 진행합니다.

- 기준 범위: `1440 × 900` ~ `1920 × 1080`
- 우선 기준: `1440 × 900`
- 확장 기준: `1920 × 1080`
- 모바일/태블릿 최적화는 1차 퍼블리싱 범위에서 제외합니다.
- 모바일/태블릿은 화면이 크게 깨지지 않는 수준의 기본 방어만 고려하고, 세부 UX는 후속 작업으로 분리합니다.

## 접근성 기준

- 버튼과 입력 요소는 키보드 접근을 고려한다.
- 상태 태그는 색상만으로 의미를 전달하지 않는다.
- 모달/사이드바는 focus trap과 닫기 동작을 고려한다.

## Figma와 코드 차이 허용 기준

- spacing은 제품 흐름을 해치지 않는 선에서 소폭 차이를 허용합니다.
- font rendering 차이는 브라우저/운영체제 차이를 감안합니다.
- `1440 × 900` 기준에서 핵심 레이아웃, 간격, 정렬, 상태 표현이 Figma와 일치해야 합니다.
- `1920 × 1080`에서는 과도하게 늘어나지 않도록 max-width, grid, content width를 조정합니다.

## 체크리스트 초안

- [ ] Figma 화면과 핵심 레이아웃이 일치한다.
- [ ] `1440 × 900`에서 핵심 레이아웃이 안정적이다.
- [ ] `1920 × 1080`에서 콘텐츠가 과도하게 늘어나지 않는다.
- [ ] 공통 컴포넌트가 재사용된다.
- [ ] 역할별 접근 흐름이 깨지지 않는다.
- [ ] 로딩/빈 상태/오류 상태가 존재한다.
- [ ] 접근성 기본 기준을 만족한다.
